# 设备模板

[快速开始](getting-started.md) · [默认操作](core-experience.md) · [文档目录](README.md)

[English](device-templates.en.md) · [核心体验](core-experience.md) · [HID 接入](hid-profiles.md)

VibeWand 提供 **VibeKey、手柄、遥控器** 三套可切换的逻辑模板。按键图展示各个控件；选择控件后可以修改单击、双击、长按、按住或方向操作。场景覆盖与手势时间单独保存，切换设备不会覆盖另一套配置。

## 当前完成程度

| 模板 | 输入路径 | 当前边界 |
| --- | --- | --- |
| VibeKey | 内置 AU05 接收器直连协议 | 已有设备后端；是否连接以实时状态为准 |
| 手柄 | macOS GameController 自动发现 USB / 已配对蓝牙手柄 | 系统支持的设备无需 HID 配置；实际连接状态与按键支持单独确认 |
| 遥控器 | 实测后导入指定接口的 HID 配置 | 已实现布局、默认动作、切换与保存；配对、按键和释放报告待实测 |

切换模板会停止旧设备输入，并同步更新悬浮面板的设备照片和按键指示。手柄默认启动系统自动识别：通过 USB 连接或在 macOS 蓝牙设置中配对后，无需导入配置。连接面板显示真实状态，提供蓝牙设置和重新检测入口；「自动识别」只表示已选择输入方式，不冒充已连接。遥控器没有 HID 配置时仍显示「待导入实测 HID 配置」。高级兼容设置可导入手柄 HID 覆盖，清除后恢复自动识别。本项目不附带猜测的设备 ID 或未经验证的按键 usage。

## 共用逻辑

同一套前进 / 后退动作根据当前状态工作：阅读时滚屏，编辑草稿时移动光标，选择器中切换候选，应用切换器中切换应用。确认和返回也沿用当前场景。动作执行仍受目标应用、输入法组合状态和焦点检查约束。

所有布局都保留：听写、前进 / 后退、会话、模型 / 强度、应用切换、确认 / Enter、删除 / 返回、原生 Escape。设备布局与应用适配分层；不会因更换设备改动应用的快捷键逻辑。

| 操作 | VibeKey 默认 | 手柄默认（全部用右手） | 遥控器默认 |
| --- | --- | --- | --- |
| 前一个 / 后一个 | 旋钮左转 / 右转 | R1 / R2 | 方向左 / 右 |
| 会话 / 切换 | 单击旋钮 | 长按 × | 单击菜单键；或长按中央确认键 |
| 确认 / Enter | OK | ○ | 单击中央确认键 |
| 模型 / 强度 | 长按旋钮 | 长按 ○ | 长按菜单键 |
| 应用切换 | 双击旋钮 | 双击 × | 双击中央确认键 |
| 删除 / 返回 | ESC | □ 退格；× 返回 | 返回键 |
| 原生 Escape | 长按 ESC | 单击 × | 长按返回键 |
| 听写 | 按住麦克风键 | 按住 △ | 按住语音键 |
| 在应用切换器中确认 | 旋钮或 OK | ○ | 中央确认键或菜单键 |

手柄全部核心操作可通过右肩键、右扳机和右侧四枚面键完成；右摇杆也提供连续导航，不要求左手持握、方向键或左摇杆。右拇指按住 △ 听写时，食指仍可操作 R1 / R2 导航。表中的面键符号以 PS5 类布局说明位置，界面统一称为「手柄」。每个动作都能改配；该布局不限定其他手柄必须采用相同物理按键。

完整手柄布局包含 19 个实体按键，并为左右摇杆分别提供上、下、左、右四个方向，共 27 个可配置输入。「摇杆」分组同时包含两根摇杆的方向与按下，照片上的方向热点与列表对应。L1 / L2、L3 / R3、四向方向键、选项、创建、主页与静音等附加按键默认不执行；触摸板滑动移动光标，短按发送鼠标左键；摇杆方向提供以下默认映射：

| 摇杆方向 | 默认行为 |
| --- | --- |
| 上 / 下 | 普通场景向下 / 向上滚屏（与旧默认相反）；选择器中上一个 / 下一个候选 |
| 左 / 右 | 按当前场景滚屏、移动光标或切候选 |
| 任一方向，应用切换器内 | 上 / 左选择前一个，下 / 右选择后一个应用 |

两根摇杆提供对称的可选入口，右手方案仍可独立完成全部核心操作。推动越过死区立即执行，保持方向持续重复，回中停止；每个方向都能单独改配「拨动 / 持续拨住」动作，不与按钮的单击 / 双击混用。系统支持的手柄通过原生后端接收按键和摇杆输入；使用高级 HID 覆盖时才需对应的实测映射。额外按键以 macOS 实际公开的控件为准。原生触摸板支持单指相对移动光标与短按左键，抬起或重新接触不会跳到触摸位置；未实现双指滚动、轻点或拖拽。

遥控器以小米蓝牙遥控器 2 Pro 的方向环、确认、语音、菜单、返回布局作为设计参考，界面统一称为「遥控器」。中央键单击确认；菜单键单击切换会话 / 浏览器标签，长按进入模型选择。在选择器内两者都可以确认。方向上 / 下、电源、主页与音量键可额外配置，默认不执行动作；这些名称不自动执行设备原生功能。NFC 不在当前接入范围内。

默认阅读方向在 0.5.5 反转：旋钮左旋、R1、摇杆上/左向下滚屏；右旋、R2、摇杆下/右向上滚屏。编辑时左右光标、选择器前后、应用切换前后保留方向。显式选择「向上滚屏 / 向下滚屏」仍按动作名称工作。

面键采用用户指定的 ○ 确认、□ 退格、× 返回习惯，并非声称复刻 PS5 系统菜单。Sony 当前系统菜单说明为 × 确认、○ 取消：[官方按键说明](https://www.playstation.com/en-us/support/hardware/ps5-button-functions/)。□ 在选择器内不执行删除；○ 确认、× 取消，均无需等待双击。升级自动迁移旧默认映射，保留不同于旧默认的自定义值与手势时间。

## 手势与配置

- VibeKey 默认双击窗口为 0.28 秒、长按为 0.55 秒；手柄与遥控器为 0.32 秒、0.65 秒。
- 单击存在双击动作时会等待双击窗口；一次双击不会先执行一次单击。选择器的确认由场景规则决定；应用切换确认不等待第二次点击。
- 听写使用按下 / 松开事件；不能用只产生一次脉冲的按键配置来假装「按住听写」。
- 恢复当前模板默认只影响该模板。恢复单项时要恢复该模板的基线，而不只是删除一个覆盖值。
- 配置保存在本机 `UserDefaults` 的 `vibeWand.deviceTemplates.v1` 中。首次迁移保留旧手势、旧输入映射与明确导入的 HID 接口；旧配置不扩散到另外两套模板。
- 切换模板、更改映射、断开连接或退出时，释放已经按住的 Fn 和应用切换修饰键，清除未完成的点击。

## 硬件接入与验收

1. 通过 USB 连接手柄或在 macOS 蓝牙设置完成配对，选择「手柄」后自动检测。连接面板应显示真实的连接状态和设备名称。
2. 遥控器或不受系统支持的手柄，先读取真实设备接口和 input elements，再导入只匹配该专用接口的 HID JSON，见 [HID 接入](hid-profiles.md)。手柄的 HID 覆盖位于「高级兼容设置」，可随时恢复自动识别。
3. 在设置的「开发者」中启用「只采集物理事件」，逐个确认按下、释放、方向、重连。关闭采集模式后验证应用动作。
4. 使用通用 HID 覆盖时，对右扳机 R2 确认其休止值、按压值及回零行为。只有「休止为 0、按压非 0」的元素才适合当前 `pulse` 绑定；其他范围需要专用归一化。回中摇杆应使用 `axis` 绑定，不能配置成普通 `absolute` 编码器，否则回中也会产生反向动作；扳机阈值仍需单独验证。
5. 使用通用 HID 覆盖时，方向环如果输出单个 hat-switch 枚举值，而不是独立按键 usage，现有 JSON 不能自动把枚举值拆成左右；需增加相应解码器。私有报告或需要厂商握手的设备也需专用 `HIDEventSource`。

当前通用 HID 支持明确接口的按钮、边沿脉冲、相对 / 位置差编码器轴和回中摇杆轴。摇杆按设备上报的逻辑范围归一化，默认启动死区为半程的 22%，释放区为 16%；越过阈值立即触发，保持 350 ms 后每 90 ms 重复，回中释放。未实现按推动幅度加速、hat 枚举拆分、多指触摸板手势或手柄震动。通用 HID 覆盖只处理配置中的按键/轴，不接入原生触摸板坐标。模板是可编辑的交互配置，并非所有型号的即插即用驱动。

## 麦克风与音频

VibeWand 当前只发送按住 Fn 的听写触发，不采集音频、不切换录音设备、不内置语音识别服务。音频由 macOS 或语音应用选择的输入设备提供。

对于作为手柄参考的 DualSense，需区分连接方式：[JoyHarness 的一手调查](https://github.com/nixihz/JoyHarness/blob/main/docs/research/dualsense-wireless-microphone.md)记录了 USB 连接时在 macOS 26.5.2 出现标准音频输入设备的实测；同份调查未发现可直接启用的 Mac 蓝牙麦克风路径。因此 USB 下可先检查系统输入列表并选择实际出现的手柄麦克风；蓝牙操作时使用 Mac 或外接麦克风。本项目未在当前手柄上复验音频。

[Sony 官方兼容说明](https://www.playstation.com/en-us/support/hardware/pair-dualsense-controller-bluetooth/)支持 Mac 的 USB / 蓝牙手柄连接，但没有承诺 Mac 内置麦克风兼容性；官方保证和 USB 实测兼容行为应分别记录。不能从 HID 静音键事件推断已经取得声音。

[小米官方产品信息](https://www.mi.com/xiaomi-bluetooth-remote-2-pro)将参考遥控器定位为带智能语音、NFC 投屏、Type-C 充电的电视配件，[官方商城目录](https://m.mi.com/commodity/list/2028)也列出这些功能。这些说明未证明 macOS 可将遥控器作为标准音频输入；语音键接入与麦克风音频接入需要分别验证。

## 后续扩展

模板只描述物理控件和手势，执行动作由应用适配层负责。新增设备应先提供可验证的事件来源，再复用现有逻辑控件；新增应用动作无需复制设备协议。进一步的智能体动作可在现有动作与应用适配层扩展，不在模板中保存脚本、访问令牌或任意命令。

## 验证范围与项目独立性

首页按输入类型展示典型设备型号；各型号的能力取决于真实输入路径与配置。AU05 输入和本机蓝牙手柄已有实机记录。手柄按键覆盖取决于 macOS 暴露的控件；USB 和触摸板体验需在目标型号上验证。遥控器预设需要实测 HID 配置，不代表所有遥控器均可即插即用。历史检查见 [AU05 记录](direct-device-plan.md)和[手柄记录](controller-input.md)。

VibeWand 与 Ulanzi、Sony、小米及其他设备提供商没有隶属、合作、赞助或背书关系。名称、商标与示例型号用于说明设备布局和适配目标，不代表任何厂商关联。
