## 设备或应用操作没有响应

| 现象 | 检查项 |
| --- | --- |
| 程序进入演示 | 在「通用」检查辅助功能权限，授权后退出并重新启动。 |
| 更新到 0.11.1 后 macOS 重新要求授权，或者辅助功能里 VibeWand 明明开着却仍进入演示 | 0.11.1 把应用的标识符从 `org.vibekey.bridge` 改成了 `org.vibewand.bridge`，而 macOS 的权限是授给标识符的。重新允许 VibeWand 即可；辅助功能列表里如果还留着旧版本的那一行 VibeWand，选中后用「−」删掉。设置、布局和密钥都会带过来；钥匙串可能会问一次，是否允许 VibeWand 读取旧版本存下的密钥。 |
| AU05 不可用 | 退出 Ulanzi Studio 和 AU05Capture；专用接口同一时刻只允许一个程序占用。必要时重新插入接收器。 |
| 找不到手柄 | 检查 USB / macOS 蓝牙配对、所选模板和实时状态。移除已导入 HID 覆盖以恢复原生自动识别。 |
| 遥控器没有事件 | 模板本身不能连接硬件；导入实测配置，并验证按下和松开报告。 |
| 有事件、无应用动作 | 检查实时模式、前台应用身份、适配开关、辅助功能权限及目标应用快捷键。 |
| 终端里按键没反应或 ESC 不删除 | 0.8.3 及之前在 Codex、Claude Code 工作时会丢掉按键，请升级到 0.8.4。之后确认前台是 iTerm2、光标停在工具自己的提示符上；状态显示“没有看到命令行提示符”时只有滚屏、Escape 和回车，见[应用适配](applications.md)。 |
| 更新后动作不符预期 | 检查当前模板和场景覆盖；恢复默认前先导出布局。 |
| 升级到 0.10.2 后手柄按键变了 | 手柄的默认布局重排过：R1 按住说命令，R2 按住听写，会话和模型在 L1，切应用是按住 L2，方向键和摇杆上推向上滚。在手柄上按 ☰ 看[按键一览](core-experience.md#按键一览)。你改过的键不会被换掉；想让 R1 / R2 回到“一步一步导航”，在「设备与按键」里把它们的“按住”设成“不执行”，再给「按下即触发 · 按住连发」选一个导航动作。 |
| 手柄一碰 L2 就切到别的应用，或一碰 R2 就开始听写 | L2 默认是按住切应用，轻按一下会回到上一个应用；R2 默认是按住听写。扳机很轻就算按下。不想要的话，在「设备与按键」里把它的“按住”改成“不执行”或别的动作。 |
| 换回 0.10.1 或更早的版本后，所有设备的按键布局都变回了默认 | 旧版读不了 0.10.2 保存的布局，会整个重置，见[设备模板](device-templates.md#手势与配置)。没有导出过的布局找不回来；回到 0.10.2 以后重新设置，或导入之前导出的文件。 |
| 手柄按键没反应，屏幕中间有一张手柄图 | 按键一览开着的时候，按键只在图上亮起，不发给应用。按 × 或 ☰ 关掉它。 |
| Fn 没有触发听写 | 聚焦输入框，用键盘测试同样的按住 Fn 操作；单独检查听写服务和麦克风。 |
| 设置或悬浮面板不见了 | 从菜单栏重新打开；关闭设置不会停止设备输入。 |

下面几项与 0.10.0 和 0.10.1 新增的功能有关：

| 现象 | 检查项 |
| --- | --- |
| 键盘布局的组合键没反应 | 确认「设备与按键」里选中的是“键盘”，并且有辅助功能权限；打字和编辑用的键要带上 ⌃、⌥、⌘ 之一，F 键、数字小键盘和扩展键可以单独用；两个控件同一组合时只有前一个生效。按过别的设备后布局会切走，要重新选回键盘。 |
| 录制组合键时按了没有反应 | “录制”按钮是灰的：键盘布局还没接上，先给辅助功能权限。按了某个键没有被录下：这个键发的不是普通按键（音量、播放、亮度这类媒体键，或键盘固件自己处理的功能），在键盘的配置工具里把它改成 F13 到 F20 再录。 |
| 组合键被别的软件抢了 | 窗口管理、输入法等工具可能先一步取走同样的组合键。在「设备与按键」里换一组。 |
| 在 DeepSeek Harness 里看不到 VibeWand 的对话 | 它列在“未分组”下，标题以“VibeWand ·”开头。已经开着的 Harness 不会发现新对话：桌面版退出后重新打开，网页版刷新；或用命令模式设置页的“在浏览器里查看对话”。 |
| 打开了“让模型看窗口截图并点击”，模型说看不到 | 在「系统设置 → 隐私与安全性 → 屏幕录制」里允许 VibeWand，然后退出并重新打开它；认图标和画面要所选的模型能看图。 |
| 模型说某个应用“读不到控件”（例如网易云音乐） | 这类应用不向辅助功能提供控件，只能看着截图操作：在「设置 → 命令模式」里打开“让模型看窗口截图并点击”（0.10.1 起）。 |
| 打开看窗口后，第一条要看图的命令等了很久 | 装好或更新以后，系统第一次认字要准备半分钟左右，之后不再需要。 |
| 接不上之前的对话 | 在 Harness 里点开过的对话由它接手，VibeWand 会开始新对话；改动命令模式的任何设置、上下文用到八成也会。 |
| 命令模式点开了菜单，却说读不到里面的选项 | 这是 0.9.0 的问题，0.10.0 起快照会把新弹出的内容排在最前。还遇到的话，到「命令模式 → 记录」里看那一条的步骤，把它读到的清单发给我们。 |
| 用说的调 Codex 的强度，停在了不是你说的那一档 | Codex 的档位不叫 low / medium / high。说“最低”“调低一档”，或者直接说按钮上的名字（Light、Standard、Extended、Extra High）。 |
| 选了 SenseVoice，听写时提示模型还没有下载 | 到「语音输入」里点“下载并准备”，约 241 MB。下载中断后再点一次会从断点继续；`huggingface.co` 连不上时会改用镜像 `hf-mirror.com`，两个都连不上就下不了。 |
| “在任何应用里边说边写”一直显示“等你在 macOS 里允许这个输入法”（0.11.2 及更早：“macOS 没有启用这个输入法组件，请再试一次”） | macOS 只使用你允许过的第三方输入法。点“开启”时 VibeWand 会请 macOS 启用它，系统设置的“键盘”页因此打开：macOS 在那里问是否允许时，点“允许”，VibeWand 会自己发现并开启。在 macOS 27.0 beta（26A5378j）上这一问不出现，“输入法 → 编辑… → +”里也没有这一类输入法可加，所以在从未允许过它的 Mac 上暂时打不开；听写照旧（原生输入框边说边写，其余应用松开后粘贴）。升级 macOS 后可以再点“向 macOS 提出请求”，点之前先退出系统设置；不想等就点“不开了”。实测见[语音输入](voice-input.md#在任何应用里边说边写--typing-as-you-speak-in-any-app)。 |
| SenseVoice 的第一句话慢 | 识别程序在你按下听写键时才启动，加载模型约两秒；空闲 5 分钟后它会退出，下一次又要这两秒。说得比两秒长就感觉不到。 |

临时签名更新后可能需要重新登记辅助功能权限。目标应用更新也可能改变控件和快捷键。

## 区分设备输入与应用适配

在「设置 → 开发者」启用物理输入采集。该模式临时占用所选设备，只显示物理事件，不发送应用快捷键、Fn 或指针操作。验证成对按下 / 松开、摇杆回中及断线重连，之后恢复实时模式再试应用操作。

通过「设置 → 开发者 → 导出诊断…」保存本地诊断文件。

诊断包含模式、连接 / 权限状态、计数器、保持按键和动作状态，不包含会话正文、音频或凭证。分享前仍请检查附件，见[问题报告说明](../CONTRIBUTING.md)。

## 确认支持范围

遥控器的配对、按钮和音频需要实测；手柄按键取决于 macOS 提供的能力，识别到手柄不代表麦克风可用。触摸板只支持单指相对移动和短按点击。强制退出后若设备不可用可重新连接；崩溃后的固件恢复尚未确认。

详细边界见[应用适配](applications.md)、[硬件](device-templates.md)及[HID 接入](hid-profiles.md)。构建错误见[开发指南](development.md)。
