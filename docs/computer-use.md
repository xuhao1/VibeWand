# Computer use

[English](computer-use.en.md) · [应用适配](applications.md) · [命令模式](command-mode.md) · [文档目录](README.md)

> **One wand to command them all.**
> 你说要做什么，VibeWand 去找到、打开、按下、把字放好；活儿还是你选的软件干。

VibeWand 的每个功能，说到底都是替你操作 Mac 上的某个应用。本页讲它怎样看界面、能做哪些动作、各个应用走哪条路，以及哪些已经验证过。怎么用见[默认操作](core-experience.md)和[命令模式](command-mode.md)。

**两部分都随 0.9.0 发布，需要 macOS 26。命令模式要先配好模型才起作用。**0.10.0 新增：可以打开的窗口截图、插件模式下可选的 Harness 工具，以及命令模式读界面的三处改进（弹出的菜单排在最前、读取应用播报的状态、把按键发给指定的控件）。

## 两种驱动方式

| | 按键驱动 | 一句话驱动（命令模式） |
| --- | --- | --- |
| 入口 | 旋钮、按键、摇杆 | 按住命令键说一句话 |
| 谁决定做什么 | 固定规则：按键加当前场景对应一个动作，不经过模型 | 你配置的模型，从 13 个工具里一步一步选（你另外交给它的不算在内） |
| 适合 | 高频、确定的动作：滚屏、移动光标、选会话、换模型、听写 | 说得出但不好按的事：“切到讨论麦克风的那个会话”“打开 Runtime.swift 那个标签页” |
| 作用范围 | [已适配的应用](applications.md)和你加的规则 | 任何读得到控件的应用，一次一个 |

两种方式用的是同一套东西：macOS 辅助功能给出的控件结构，加上合成的按键、滚轮和指针事件。它们也接得上：一句话打开了应用自带的搜索以后，“转动选一个、按一下确认”仍然交回按键。

## 它怎样看界面

常见的 computer use 让模型看截图、输出坐标。VibeWand 走的是另一头：只读有名字的控件，按的也是那个控件本身。它读的是应用通过 macOS 辅助功能公开的控件树，读屏软件用的是同一份。所以它需要你在「系统设置 → 隐私与安全性 → 辅助功能」里授权；默认不需要屏幕录制权限，也不截图。

截图是命令模式里一个可以打开的补充，默认关闭，见[让模型看窗口截图](command-mode.md#让模型看窗口截图)。打开后模型可以要一张被操作的那个窗口的图，图上标着控件的编号：它用眼睛认，按的仍然是控件，不点坐标。按键驱动的部分不受这个开关影响，从不截图。

| 读什么 | 用来做什么 |
| --- | --- |
| 前台应用的 bundle ID | 决定用哪个适配；不在名单里的应用收不到应用动作 |
| 窗口和焦点控件的身份 | 把动作绑在按键那一刻的目标上 |
| 焦点是不是可编辑的输入框，草稿空不空 | 决定转动是滚屏还是移动光标，ESC 是取消还是删除 |
| 会话、模型、强度列表开没开，有哪些行，选中了哪行 | 候选导航；当前行的标题只显示在悬浮面板上 |
| 输入框旁带名称的按钮，侧边栏的会话列表 | 直接按下模型、强度、搜索按钮；在 DeepSeek Harness 里逐行选会话 |
| 输入法是否正在组字，有没有不认识的弹窗 | 这两种情况只发原生的回车和 Esc |
| 终端里光标附近的几行文字 | 判断光标是不是停在认识的提示符上、提示符里有没有草稿、提示符是不是被列表盖住了 |
| 命令模式另外读：窗口标题，前台窗口里控件的类型、名称和状态，菜单栏；输入文字前后输入框的字数和光标位置；应用播报给读屏软件的状态行，网页控件自己声明的操作按键（0.10.0 起） | 让模型找到要按的那个控件；确认输入的文字确实进去了；知道一个靠按键调节的控件现在停在哪一档、用哪个键调 |

不读的东西：会话正文、文档内容、选中的文字。输入框的内容只归约成“空”或“有字”。剪贴板只在粘贴时暂存，随后还原。命令模式的控件清单跳过静态文字和图片，只留按钮、标签页、菜单项、输入框、列表行这类控件。0.10.0 起有一个例外：应用标成“状态”或“提醒”、读屏软件会念出来的那一行播报也读，例如 Codex 调强度时的“GPT-6 Astra Extra High, 4 of 5.”；超过 80 个字的播报不读。

终端是唯一读文字的地方。它把整个界面画成文字，没有输入框控件，所以 VibeWand 读光标上方最多 12 行到屏幕末尾，不读回滚区；在内存里归约成“空提示符、有草稿、列表开着、别的画面”这几种状态后就丢弃，不保存、不写日志、不导出。

Electron 应用（例如 DeepSeek Harness、WorkBuddy）默认不向辅助功能公开网页内容，VibeWand 第一次遇到时会请它公开。

## 它能做的动作

按键驱动时，一次按键对应下面的一个动作：

| 动作 | 怎么做 | 用在哪 |
| --- | --- | --- |
| 按下控件 | 辅助功能的“按下”；候选行按不动时，改为在它的中心点一下 | 模型和强度按钮、WorkBuddy 的搜索按钮、候选行 |
| 调滑块 | 辅助功能的增、减 | Codex、Claude 的推理强度 |
| 发按键 | 向目标应用发合成按键 | `⌘K`、`⌃Tab`、`⌘L`、方向键、回车、Esc、退格 |
| 滚动 | 在对话区的位置发滚轮事件，指针随后回到原处 | 阅读回复 |
| 移动指针 | 停到当前候选行上，结束后回到原处；手柄触摸板直接移动指针，短按点击 | 模型列表、Harness 侧边栏；触摸板在任何应用里都能用 |
| 写字 | 原生输入框边说边改本次听写的那一段；其余应用在松开后粘贴一次，剪贴板随后恢复 | 听写，任何应用 |
| 输入命令 | 只在空提示符下粘贴 `/resume` 或 `/model`，等这一行只剩这条命令才回车 | 终端里的 Claude Code、Codex、OpenCode |
| 切换应用 | 调出系统的应用切换器，转动选择，确认 | 任何应用 |

## 命令模式的 13 个工具

默认情况下模型能做的事就是这张表，没有别的：没有命令行，没有文件读写，没有网页访问，没有坐标点击。你可以另外交给它两样，都要自己打开：第 14 个工具 `ui_screenshot`（看被操作的那个窗口的截图）；插件模式下你那份 DeepSeek Harness 自带的命令行、文件、网页等工具。见[模型能用什么](command-mode.md#模型能用什么)。

| 工具 | 作用 | 类别 |
| --- | --- | --- |
| `list_targets` | 列出能操作的应用、是否在运行，以及你说话时所在的应用和窗口 | 读 |
| `find_sessions` | 查询应用自己的会话列表：标题、项目文件夹、更新时间。目前只有 Codex | 读 |
| `open_session` | 打开查到的某个会话，把应用带到前台 | 导航 |
| `search_in_app` | 把应用带到前台，打开它自带的搜索并填入关键词，之后由你用旋钮选 | 导航 |
| `activate_app` | 把应用带到前台，可以同时打开一个文件或网址 | 导航 |
| `ui_snapshot` | 列出前台窗口的控件：编号、类型、名称、状态。0.10.0 起，上一次快照之后新出现或变了的排在最前，按一下弹出来的菜单不会埋在长窗口的末尾；应用的模型选择器会标出来 | 读 |
| `ui_press` | 按下快照里的某个控件 | 导航 |
| `ui_key` | 发一个快捷键，例如 `cmd+p`、`ctrl+tab`、`escape`。0.10.0 起可以指定发给哪个控件（它先获得键盘焦点），用来调节靠方向键调的那一类控件；一次一下，返回里带上应用随后播报的内容 | 导航 |
| `ui_menu` | 按标题路径选一个菜单栏项目，例如“文件 → 打开最近使用 → notes.md” | 导航 |
| `ui_type` | 往输入框里写字，不按回车 | 写 |
| `choose` | 在悬浮面板上列出最多六个候选，由你用旋钮选 | 问你 |
| `finish` | 结束，用一句话告诉你结果 | 问你 |
| `need_user` | 做不下去时停下来，说明缺什么 | 问你 |

一条命令最多 24 步、120 秒。问题 45 秒没人回答视为取消。

## 各应用走哪条路

| 应用 | 按键驱动（已发布） | 命令模式找会话 |
| --- | --- | --- |
| Codex | `⌘K` 面板；强度滑块和模型列表 | 查询 Codex 自己的会话列表，取最近 60 个按标题和项目文件夹筛选，用 `codex://threads/…` 打开。列表只有本机的会话；没有匹配或查不到时，打开 `⌘K` 面板并填入关键词 |
| Claude | `⌘K` 面板；模型菜单，然后强度滑块 | 打开 `⌘K` 搜索，填入关键词，你用旋钮选 |
| DeepSeek Harness | 侧边栏会话列表；两级模型菜单 | 进入侧边栏会话列表，你用旋钮逐行选；那里没有可以填词的搜索框 |
| WorkBuddy | 侧边栏搜索任务；模型菜单 | 打开全局搜索，填入关键词 |
| 飞书 / Lark | `⌘K` 搜索、切换聊天 | 打开 `⌘K` 搜索，填入关键词 |
| 微信 | `⌘F` 搜索，兼容映射 | 发 `⌘F`；识别到搜索打开才填词 |
| iTerm2 里的 Claude Code、Codex、OpenCode | 空提示符下输入 `/resume`、`/model`，列表里用方向键、回车、Esc；有草稿时移动光标、删除 | 没有专门的通道 |
| 浏览器 | 下一标签页、地址栏、滚屏 | 没有会话 |
| 其他应用 | 你加的快捷键规则；听写、切换应用 | 没有会话 |

命令模式里“切应用、打开文件或网址”和“操作前台窗口”不分应用：凡是读得到控件的窗口都一样，用 `ui_snapshot` 看，用 `ui_press`、`ui_key`、`ui_menu`、`ui_type` 做。

## 不变的规矩

这些约束写在代码里，不靠模型自觉。

- **不替你发送。** 听写松开后不按回车；命令模式写进去的字同样停在输入框里，除非你的命令明说要发送。
- **动作绑定按键那一刻的目标。** 按下时记下应用、窗口和焦点，执行前再核对一次，变了就丢弃。命令模式只操作一个应用：你说话时在前台的那个，或它替你切到的那个；你切走以后，后面的步骤作废。
- **有后果的操作默认每次都问，问多少由你定。** 命令模式有三档权限：只确认有后果的操作（默认），即名称带删除、丢弃、不保存、发送、提交、支付等字样的按钮和菜单项（0.10.0 起加上允许、授权、批准、同意这类交出权限的），多行输入框里的回车，以及 `⌘回车`、`⌘⌫`、`⌘Q`；每一步都先在设备上确认；或者完全不问。确认由网关执行，模型绕不过去。交给模型的 Harness 工具由 Harness 的沙箱按同一档位管，它要越出沙箱时同样经网关问你。
- **密码框不写入。** 听写和命令模式都一样。
- **输入法候选和不认识的弹窗只收原生的回车和 Esc，** 不会被当成“发送”或“搜索”。
- **应用按名单识别。** 完整的 bundle ID 精确匹配，不看窗口标题和网页地址。未适配或被你关掉的应用收不到应用动作。
- **悬浮面板不抢焦点。** 候选由设备选择，原来的输入框和选区不受影响。
- **配置不执行脚本，不保存凭证。** 密钥在钥匙串里。
- **随时能停。** 返回键取消；命令模式下再说一句，会立刻打断上一句。

命令模式会把哪些内容发给模型服务，见[发出去的内容](command-mode.md#发出去的内容)。关闭命令模式或没有配置模型时，VibeWand 不读取那些内容，也不联系任何模型服务来决定动作。它每一步做了什么、模型看到了什么，都能在[Agent 记录](command-mode.md#agent-记录)里看到。

## 做不到的

- 画布、游戏和自绘界面：没有控件可读。打开截图后模型能看见它们，仍然按不了。
- 终端里只认 Codex、Claude Code、OpenCode 的提示符，并且以 iTerm2 为准。tmux 右侧窗格里的提示符、Terminal.app 等其他终端、没有适配的命令行工具都不识别，其余边界见[应用适配](applications.md#终端里的-claude-codecodexopencode)。
- 微信的聊天控件读不到，只有 `⌘F` 的兼容映射。
- 需要看画面才能判断的事，除非你打开了命令模式的窗口截图。按键驱动的部分不看屏幕。
- 把选中的内容交给另一个工具，以及“在一个工具里跑完、把结果交给另一个”的接力，尚未实现。
