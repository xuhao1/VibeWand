# VibeWand

**许可声明：允许个人非商用使用；商用必须联系[作者徐浩](https://github.com/xuhao1)，并取得单独的商业许可。**

**用手边的实体控制器，操作 macOS 上的 AI 工作流。**

转动阅读、按下切换、按住听写。VibeWand 把控制器接入你正在使用的应用，用原生悬浮面板反馈每次操作，并在同一个设置窗口里配置所有手势。

[English](README.md) · [核心体验](docs/core-experience.md) · [文档目录](docs/README.md) · [非商用许可证](LICENSE)

VibeWand 原名 **VibeKey Bridge**。当前 **0.5.5** 是持续开发中的 macOS 原型，使用 Swift、AppKit、辅助功能、GameController 和 IOKit。VibeKey 使用 AU05 专用后端，系统支持的手柄自动接入；遥控器与可选的 HID 兼容模式需要实测配置。

## 核心功能

- **同一套控件，按场景工作。** 阅读时滚屏，有字的草稿中移动光标，选择器中切候选，也能切换 macOS 应用。
- **按住听写。** 麦克风键按下 / 松开对应 Fn 按住 / 松开，配合已配置的输入法；音频仍由 macOS 和输入法处理。
- **适配前台应用。** Codex 与 DeepSeek Harness 复用 AI 操作逻辑，浏览器、微信和飞书使用各自的键盘映射；可为其他应用添加聊天工具、浏览器或自定义规则，编辑其快捷键。
- **在设备照片上配置按键。** 点击真实产品照片风格的设备图，或在按键列表中选择控件，在右侧编辑触发方式。动作库支持搜索，并按系统功能、应用功能、VibeWand 内功能分类，更改即本地保存。
- **三套设备模板。** VibeKey、手柄、遥控器分别保留手势配置；手柄默认操作全部安排在右手可及的位置，其他按键也可自由配置。
- **手柄触摸板控制光标。** 单指滑动移动 Mac 光标，短按触摸板点击；默认 ○ 确认、□ 退格、× 返回，阅读滚屏方向使用反转后的默认配置。
- **中英文界面。** 在「通用」切换语言，无需重启；设置、菜单、动作名称和悬浮提示同步更新。
- **原生悬浮反馈。** 实时显示按下、松开和旋转，不抢输入焦点；支持大小、透明度、按键说明与图片导出。右上角齿轮可打开设置，× 可隐藏面板并从菜单栏重新显示，设置窗口打开期间也显示 Dock 图标。
- **独立设备工具。** AU05 专用后端、macOS 手柄自动识别、标准 HID 配置导入，以及用于检查事件的命令行采集器。

运行无需 Ulanzi Studio、Electron、云服务或 API Key。VibeWand 本身不提供模型，也不替代目标应用或语音输入法。

## 开始使用

要求 macOS 13+、Swift 5.9+ 工具链。运行测试建议使用 Xcode。

```sh
bash scripts/build-app.sh
bash scripts/run.sh
```

生成 `dist/VibeWand.app`。如果本机有 `/Applications/Xcode-beta.app`，构建脚本优先使用它，否则使用当前选定的开发工具链。

1. 使用 AU05 时先退出 Ulanzi Studio；检测到 Studio 运行时，VibeWand 会让出设备。
2. 在「系统设置 → 隐私与安全性 → 辅助功能」允许 **VibeWand**。
3. 从菜单栏打开「设置…」，在「设备与按键」选择模板，系统支持的手柄通过 USB 连接或 macOS 蓝牙配对后自动识别。「连接设备…」查看实时状态、打开蓝牙设置或管理高级 HID 配置；「通用」显示设备与授权状态。
4. 切到支持的应用，再操作控制器。没有辅助功能权限时，程序以演示模式启动。

没有设备也可以体验：

```sh
bash scripts/run.sh --demo --settings
```

启动参数仅对新进程生效；已有实例运行时请先退出。

## VibeKey 默认操作

| 手势 | 默认行为 |
| --- | --- |
| 阅读 / 空草稿时左旋、右旋 | 向下、向上滚屏 |
| 有字的草稿中左旋、右旋 | 光标向左、向右移动 |
| 选择器中左旋、右旋 | 上一个、下一个候选 |
| 旋钮单击 | 打开会话；选择器内确认；浏览器内下一标签页 |
| 旋钮双击 | 打开 macOS 应用切换，旋转选择，单击确认 |
| 旋钮长按 | 在支持的 AI 应用中打开模型入口 |
| 麦克风按住 / 松开 | 保持 / 释放 Fn 听写 |
| OK 单击 | 确认候选或 Return |
| ESC 单击 | 编辑草稿时删除光标前字符 / 选区，其他场景取消 |
| ESC 长按 | 原生 Escape |

浏览器中旋转优先滚动页面，即使焦点在网页输入框中。微信和飞书通过键盘映射复用阅读、编辑、搜索、确认与取消；Return 是否发送消息由目标应用的设置决定。完整行为及支持边界见 [核心体验](docs/core-experience.md)。

双击间隔默认 0.28 秒，长按默认 0.55 秒，均可调整。配置了「按住 / 松开」动作时，这次按压优先执行该动作，不再附带单击、双击或长按，避免听写结束后意外确认或发送。按住旋转仅适用于 VibeKey 旋钮，手柄和遥控器没有隐藏的组合键。

## 统一设置

原生 macOS 设置窗口用侧栏组织六个页面，导航整行均可点击，语言设置统一放在「通用」。0.5.3 为通用、设备、应用、悬浮面板、开发者、关于六页，以及四种配置弹窗加入原生半透明材质，并跟随 macOS 明暗外观。紧凑标题、统一间距和对齐控件保持信息清晰，滑块直接显示当前数值。

布局编辑参考 Steam Input：左侧是设备照片和按键列表，右侧是当前按键的设置，修改手势时打开动作库。手柄使用限高横向照片，下面列出按键及八个摇杆方向；VibeKey 和遥控器使用竖向照片，与按键列表并排，更充分利用窗口空间。打开设置后 VibeWand 出现在 Dock；最小化后可从 Dock 恢复，关闭设置后继续作为菜单栏应用运行，设备控制不中断。

| 页面 | 内容 |
| --- | --- |
| 通用 | 界面语言、设备与前台应用状态、辅助功能权限、听写说明 |
| 设备与按键 | 模板、可点击设备照片、按键分组、按场景手势、动作库、时间参数、配置导入 / 导出 |
| 应用适配 | 内置适配开关、自定义聊天工具 / 浏览器 / 自定义规则及快捷键 |
| 悬浮面板 | 显示、说明、大小、透明度、导出图片、位置 |
| 开发者 | 演示、只采集物理事件、兼容选项、诊断与重新连接 |
| 关于 | 版本、许可、作者以及个人 / 项目主页链接 |

![VibeWand 原生设置与手柄布局](docs/images/settings-native.png)

*从已实现的原生设置界面渲染。可浏览 [全部页面外观图集](docs/ui-appearance-gallery.html)、[外观审查记录](docs/ui-appearance-audit.md)、[设置设计](docs/settings-design.md) 及 [设备图像设计](docs/design-device-assets.md)。*

先选择模板和实体按键，再选作用场景，点击触发方式分配动作。动作库区分当前配置与模板默认，搜索无结果时也有明确提示。「恢复默认动作」恢复继承，「不执行」明确禁用该手势。顶部直接提供「导入」「导出」「恢复默认」，管理当前模板的手势配置；硬件 HID 配置在「连接设备…」中独立管理。

## 设备状态

| 设备 / 模板 | 当前支持程度 |
| --- | --- |
| VibeKey | AU05 专用 vendor HID 直连；已观察到接收器握手和全部六类物理输入 |
| 手柄 | USB 连接或蓝牙配对后通过 macOS GameController 自动发现；系统支持的设备无需导入 HID 配置 |
| 遥控器 | 可编辑交互模板；macOS 配对、按键事件与音频可用性仍需实测 |
| 其他标准 HID 控制器 | 明确的 VID / PID / 接口配置；支持按钮、脉冲、编码器轴与回中摇杆轴 |

手柄与遥控器使用通用名称。手柄提供 19 个实体按键与左右摇杆的八个方向，共 27 个可配置输入；每个摇杆方向可独立分配动作，HID 轴接入处理回中死区、迟滞、持续重复与回中释放。遥控器提供 12 个按键。新增按键默认不执行，按需分配。各模板分别保存手势与设备配置；切换手柄后自动检测设备，悬浮面板同步切换成手柄布局，连接面板区分「自动识别」与实际连接状态。遥控器仍需导入实测 HID 配置。已导入的配置会覆盖当前模板的默认连接；手柄可移除覆盖并恢复自动识别。选择模板不会替代系统蓝牙配对，也不会启用麦克风。AU05 的 USB 音频与固件由系统管理。完整按键支持取决于 macOS 对该型号实际提供的控件；目标硬件的输入与完整听写链路仍需逐项验证，导入配置前请阅读 [HID 接入文档](docs/hid-profiles.md)。

## 开发与诊断

```sh
swift build
swift test
swift run AU05Capture --list
swift run AU05Capture --duration 30
swift run AU05Capture --profile /absolute/path/controller.json --duration 30
```

`AU05Capture` 向 stdout 输出 NDJSON 事件，连接状态写入 stderr。GUI 与采集器不能同时接管 AU05。正常退出、SIGINT、SIGTERM 会释放接口及临时 hooks。

| 目录 | 内容 |
| --- | --- |
| `Sources/AU05Device` | 协议、设备发现、直连生命周期、通用 HID |
| `Sources/VibeKeyBridge` | 原生 UI、手势、应用适配、悬浮面板、听写与应用切换 |
| `Sources/AU05Capture` | 命令行采集器 |
| `Tests` | 协议、生命周期、手势、适配与交互测试 |
| `profiles` | 手势和通用 HID 示例 |
| `docs` | 使用体验、设计、接入和历史记录 |

内部 target `VibeKeyBridge` 与 bundle identifier `org.vibekey.bridge` 保留，延续模块引用和既有偏好；应用与可执行文件名改为 VibeWand。

签名可通过 `VIBEWAND_SIGNING_IDENTITY` 指定，兼容旧变量 `VIBEKEY_SIGNING_IDENTITY`。未指定时使用唯一的 Apple Development 身份，否则回退临时签名；临时签名更新后可能需要重新登记辅助功能权限。构建成功才替换 App，旧包保留在 `dist/.previous-build.*`。

程序通过辅助功能读取前台控件并发送本地键盘 / 指针事件，不录制音频，不上传会话。读取草稿时只保留「是否为空」的判断，诊断不包含正文、音频或凭证。开发者选项提供演示与物理采集，也可导出本地诊断快照：

```sh
bash scripts/run.sh --capture-only --diagnostics-path /absolute/path/status.json
```

采集模式会临时接管所选设备，只显示物理事件，不发送应用或听写动作。演示模式使用模拟草稿与会话。
